Section 01

Overview

Objective

Understand how environmental monitoring and hardware control can be extended with autonomous edge logic, time-series data persistence, and analytical data export for external investigation.

Problem Being Addressed

Standard monitoring dashboards show only current telemetry snapshots. Once a browser tab closes or the microcontroller reboots, instantaneous sensor readings vanish. Furthermore, manual control remains inefficient for conditions that follow clear physical parameters (such as darkness falling in an office). This activity addresses both challenges by adding autonomous closed-loop lighting automation and a persistent time-series database pipeline with downloadable CSV dataset exports.

Summary & Expected Purpose

I implemented an end-to-end cyber-physical architecture. The ESP32 measures environmental conditions (DHT11 temperature/humidity and LDR light levels) and evaluates automated control rules (switching the relay when light levels cross calibrated thresholds). Concurrently, sensor readings and actuator states are committed to Firebase with Unix timestamps. The web dashboard visualizes chronological tables and trend charts while enabling users to export the complete historical log to CSV.

Section 02

Concepts

This activity synthesizes embedded control theory, time-series data management, and data science workflows:

Autonomous Closed-Loop Control & Hysteresis

In Automatic Mode, the microcontroller executes feedback control: if ambient light measured by the LDR falls below a defined lux threshold, the relay triggers immediately. To prevent rapid on/off flickering (relay chatter) near the transition boundary, software hysteresis applies distinct turn-on (e.g. < 350) and turn-off (e.g. > 450) thresholds.

Time-Series Data Logging in Cloud Databases

Instead of overwriting a single variable, historical logging writes entries with unique keys under a /history/logs/ node. Each record captures the timestamp, temperature, humidity, light value, bulb state, and operating mode.

Client-Side Data Export (CSV Generation)

The web dashboard queries the historical dataset, transforms the JSON records into comma-separated value (CSV) formatting, and instantiates an in-memory Blob object triggered via an automated download link. This empowers analysts to ingest live IoT telemetry into Python, pandas, or Excel.

Section 06

Implementation

ESP32_Logging_And_Export.ino 
#include <WiFi.h>
#include <FirebaseESP32.h>
#include <DHT.h>
#include "time.h"

#define WIFI_SSID       "YOUR_WIFI_SSID"
#define WIFI_PASSWORD   "YOUR_WIFI_PASSWORD"
#define FIREBASE_HOST   "YOUR_PROJECT_ID-default-rtdb.firebaseio.com"
#define FIREBASE_AUTH   "YOUR_FIREBASE_SECRET"

#define DHTPIN          4
#define LDRPIN          34
#define RELAYPIN        26

DHT dht(DHTPIN, DHT11);
FirebaseData fbdo;
FirebaseAuth auth;
FirebaseConfig config;

// Automation parameters
bool autoMode = true;
const int LIGHT_ON_THRESHOLD  = 350;
const int LIGHT_OFF_THRESHOLD = 500;
unsigned long lastLogTime = 0;

void setup() {
  Serial.begin(115200);
  pinMode(RELAYPIN, OUTPUT);
  dht.begin();

  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) delay(500);

  // Sync NTP Time for accurate logging timestamps
  configTime(0, 0, "pool.ntp.org");

  config.host = FIREBASE_HOST;
  config.signer.tokens.legacy_token = FIREBASE_AUTH;
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true);
}

void loop() {
  // 1. Read environmental conditions
  int lightValue = analogRead(LDRPIN);
  float temp = dht.readTemperature();
  float hum = dht.readHumidity();

  // 2. Fetch mode control from Firebase
  if (Firebase.getBool(fbdo, "/controls/autoMode")) {
    autoMode = fbdo.boolData();
  }

  // 3. Autonomous Lighting Logic with Hysteresis
  if (autoMode) {
    if (lightValue < LIGHT_ON_THRESHOLD) {
      digitalWrite(RELAYPIN, HIGH);
    } else if (lightValue > LIGHT_OFF_THRESHOLD) {
      digitalWrite(RELAYPIN, LOW);
    }
  } else {
    if (Firebase.getBool(fbdo, "/controls/manualBulb")) {
      digitalWrite(RELAYPIN, fbdo.boolData() ? HIGH : LOW);
    }
  }

  // 4. Time-series logging every 10 seconds
  if (millis() - lastLogTime > 10000) {
    lastLogTime = millis();
    time_t now;
    time(&now);

    FirebaseJson logEntry;
    logEntry.set("timestamp", (int)now);
    logEntry.set("temp", temp);
    logEntry.set("humidity", hum);
    logEntry.set("light", lightValue);
    logEntry.set("bulbState", digitalRead(RELAYPIN) == HIGH);
    logEntry.set("mode", autoMode ? "AUTO" : "MANUAL");

    Firebase.pushJSON(fbdo, "/history/logs", logEntry);
    Serial.println("Pushed historical record to Firebase");
  }
}

Client-Side CSV Export Function

exportDataToCSV.js 
function exportLogsToCSV(logsData) {
  let csvContent = "data:text/csv;charset=utf-8,";
  csvContent += "Timestamp,ISO_Date,Temperature_C,Humidity_Pct,Light_ADC,Bulb_Status,Mode\n";

  Object.values(logsData).forEach(row => {
    const dateStr = new Date(row.timestamp * 1000).toISOString();
    csvContent += `${row.timestamp},"${dateStr}",${row.temp},${row.humidity},${row.light},${row.bulbState},${row.mode}\n`;
  });

  const encodedUri = encodeURI(csvContent);
  const link = document.createElement("a");
  link.setAttribute("href", encodedUri);
  link.setAttribute("download", `iot_telemetry_${Date.now()}.csv`);
  document.body.appendChild(link);
  link.click();
  document.body.removeChild(link);
}
Section 07

Configuration

Sensor Calibration & Setup

  1. LDR Calibration: Test raw ADC readings under bright room light (~1500–2500) and hand-covered darkness (~100–300). Set turn-on threshold to 350 and turn-off threshold to 500 to establish an effective 150-unit hysteresis band.
  2. NTP Time Synchronization: Configure the NTP pool server in firmware to ensure telemetry records carry valid Unix timestamps rather than relative processor uptime.
  3. Logging Rate Optimization: Throttle the logging frequency to 10–30 second intervals to maintain comprehensive trend records without exceeding database usage caps.

Section 09

Challenges & Fixes

Problem Relay chatter (rapid clicking on and off) when ambient light hovered near the threshold.
Investigation A single threshold point (if (light < 400) ON else OFF) caused minor sensor noise to rapidly flip states.
Solution Introduced software hysteresis with separate activation (<350) and deactivation (>500) boundaries.
Outcome Completely stable, chatter-free transitions under gradual lighting changes.
Problem Firebase database filled up with thousands of redundant entries during testing.
Investigation The firmware was writing to /history/logs on every iteration of loop() without throttling.
Solution Implemented a non-blocking 10-second timer using millis() and restricted logging to significant change deltas.
Outcome Clean, organized datasets operating well within free-tier cloud limits.

Reflection

I explored how monitoring, automatic lighting, and historical records can contribute to a more complete system, while learning why collected data can be useful for further analysis. Transitioning from fleeting real-time values to persistent records that can be exported for data science workflows demonstrated how physical embedded systems connect with broader enterprise data pipelines."

Limitations & Future Improvements

While the current prototype successfully logs and exports CSV records, future revisions could incorporate edge-level SD card buffering to preserve telemetry during Wi-Fi outages and implement automated cloud functions to compute daily aggregates (average, min, max) automatically.
