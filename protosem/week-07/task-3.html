Section 01

Overview

Objective

Understand how external events and condition triggers can initiate actions in an IoT system automatically without requiring continuous manual user intervention.

Problem Being Addressed

In Tasks 1 and 2, every hardware actuation required a human user to manually press a button on a local webpage or cloud dashboard. However, real-world cyber-physical systems demand autonomy: street lights should respond to twilight or sunrise schedules, alarms should trigger on geofence entry, and notifications should dispatch based on weather alerts. This activity addresses the need for automated event chaining by linking third-party web triggers to physical hardware via cloud pipelines.

Summary & Expected Purpose

Using IFTTT (If This Then That), I constructed an event-driven automation pipeline. An incoming digital trigger (such as a webhook event, schedule condition, or external API action) activates an IFTTT Applet. The Applet communicates with the Adafruit IO service, publishing an updated payload to our designated feed. The ESP32 receives the event via MQTT and executes the corresponding hardware action.

Section 02

Concepts

Automating actions across disparate web services requires understanding service orchestration and event-driven architectures:

The Concept of IoT Automation

IoT automation removes the human bottleneck. Rather than waiting for a person to flip a switch, a software rule continually evaluates state conditions and dispatches instructions when pre-configured criteria are met.

What IFTTT Is and Why It Is Used

IFTTT (If This Then That) is a web-based integration service that connects hundreds of popular digital services (Google Calendar, Webhooks, Location Services, Weather, Telegram, Adafruit IO). It allows developers to create conditional statements ("Applets") without writing custom server backends or managing continuous polling infrastructure.

The Trigger → Action Paradigm

  • Trigger ("If This"): An external event that starts the execution (e.g., an HTTP webhook call or a scheduled time of day).
  • Action ("Then That"): The resulting operation executed by IFTTT (e.g., sending data to an Adafruit IO feed).

Role of Adafruit IO in Automation

Adafruit IO bridges the high-level web service (IFTTT) with the low-level embedded hardware. By receiving the webhook payload from IFTTT, Adafruit IO converts it into an MQTT broadcast delivered to the ESP32 in sub-second latency.

Section 03

System Design

The event-driven system architecture routes signals through four distinct tiers:

Event-Driven Automation Flow
1 Trigger or Event
2 IFTTT Automation Applet
3 Adafruit IO Platform
4 MQTT Message Stream
5 ESP32 Microcontroller
6 Hardware Response

The trigger fires independently of the ESP32. IFTTT connects to Adafruit IO via authenticated REST API, which automatically triggers MQTT pub/sub transmission down to the listening ESP32 client.

Layered Roles in the Architecture

Tier Component Responsibility
Event Source Webhook / Web Trigger Generates the initial event signal when condition is satisfied.
Orchestration Tier IFTTT Service Evaluates rule logic and invokes Adafruit IO REST API endpoint.
IoT Broker Tier Adafruit IO (MQTT) Receives API data and publishes payload to feed topic.
Physical Edge Tier ESP32 + Actuator Receives MQTT packet and toggles GPIO output pin.

Service Linkage Setup

  1. Log into IFTTT and click Create.
  2. In the If This block, select the trigger service (e.g., Webhooks with event name iot_trigger, or Button Widget).
  3. In the Then That block, search for Adafruit and select Send data to Adafruit IO.
  4. Authorize IFTTT to access your Adafruit IO account.
  5. Select your feed name (led-control) and set the data to save (e.g. 1 or ON).
  6. Save and activate the Applet.
Section 06

Implementation

The ESP32 firmware continuously monitors the MQTT feed for updates resulting from automated IFTTT executions:

ESP32_IFTTT_Automation_Receiver.ino 
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

// Wi-Fi Credentials
#define WLAN_SSID       "YOUR_WIFI_SSID"
#define WLAN_PASS       "YOUR_WIFI_PASSWORD"

// Adafruit IO Broker Credentials
#define AIO_SERVER      "io.adafruit.com"
#define AIO_SERVERPORT  1883
#define AIO_USERNAME    "YOUR_AIO_USERNAME"
#define AIO_KEY         "YOUR_AIO_KEY"

const int ledPin = 2;

WiFiClient client;
Adafruit_MQTT_Client mqtt(&client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);
Adafruit_MQTT_Subscribe autoFeed = Adafruit_MQTT_Subscribe(&mqtt, AIO_USERNAME "/feeds/led-control");

void MQTT_connect();

void setup() {
  Serial.begin(115200);
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);

  WiFi.begin(WLAN_SSID, WLAN_PASS);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nWiFi Connected! Listening for automated IFTTT events...");

  mqtt.subscribe(&autoFeed);
}

void loop() {
  MQTT_connect();

  Adafruit_MQTT_Subscribe *subscription;
  while ((subscription = mqtt.readSubscription(5000))) {
    if (subscription == &autoFeed) {
      char *payload = (char *)autoFeed.lastread;
      Serial.print("[Automated Event Triggered] Payload: ");
      Serial.println(payload);

      if (strcmp(payload, "1") == 0 || strcasecmp(payload, "ON") == 0) {
        digitalWrite(ledPin, HIGH);
        Serial.println("Action Executed: Hardware turned ON via IFTTT automation");
      } else if (strcmp(payload, "0") == 0 || strcasecmp(payload, "OFF") == 0) {
        digitalWrite(ledPin, LOW);
        Serial.println("Action Executed: Hardware turned OFF via IFTTT automation");
      }
    }
  }

  if (!mqtt.ping()) {
    mqtt.disconnect();
  }
}

void MQTT_connect() {
  int8_t ret;
  if (mqtt.connected()) return;
  Serial.print("Connecting to MQTT... ");
  while ((ret = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(ret));
    mqtt.disconnect();
    delay(5000);
  }
  Serial.println("Connected!");
}
Section 07

Configuration

To configure this automation pipeline securely:

Setup Verification Steps

  1. In the IFTTT Applet settings, ensure the Receive notifications when this Applet runs option is checked for testing.
  2. Trigger the event manually or test the webhook using curl -X POST https://maker.ifttt.com/trigger/iot_trigger/with/key/YOUR_IFTTT_KEY.
  3. Observe the IFTTT Activity log: verify status reports "Applet ran".
  4. Check Adafruit IO feed history: verify new timestamped entry added by user "IFTTT".
  5. Verify ESP32 Serial Monitor log: confirm payload arrival and GPIO actuation.

Section 09

Challenges & Fixes

Problem Noticeable delay (up to 45 seconds) between trigger firing and hardware LED toggling.
Investigation Certain polling-based IFTTT triggers only check for new events periodically rather than dispatching instantly.
Solution Configured a direct Webhook trigger (Maker Webhooks) with immediate push dispatch.
Outcome End-to-end execution latency dropped to under 1.5 seconds.
Problem Applet failed with "Action error: Feed Not Found".
Investigation The feed had been renamed in Adafruit IO from "LED Control" to "led-control", breaking the initial IFTTT dropdown cache.
Solution Refreshed connected service credentials in IFTTT settings and re-selected the active slug.
Outcome 100% reliable trigger-to-feed message transmission.
