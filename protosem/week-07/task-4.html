Section 01

Overview

Objective

Understand how environmental sensor telemetry, cloud database services, and a customized web dashboard work together to provide continuous physical monitoring and remote hardware control.

Problem Being Addressed

While previous tasks explored basic binary actuation, real-world IoT systems primarily gather continuous environmental analog/digital telemetry (temperature, humidity, light) and synchronize it in real-time across multiple authenticated client interfaces while enabling bidirectional control. This task addresses building a synchronized multi-client cloud interface backed by a persistent NoSQL database.

Summary & Expected Purpose

I developed a comprehensive IoT monitoring prototype. The ESP32 continuously samples temperature and relative humidity from a DHT11 sensor and ambient illumination from an LDR light sensor. Telemetry is streamed over Wi-Fi directly into Google Firebase Realtime Database. A custom web dashboard listens to the database nodes in real-time, visualizes live telemetry gauges, and provides an authenticated toggle to switch an electrical bulb via an isolated relay.

Section 02

Concepts

This activity incorporates fundamental concepts of cloud architecture, databases, security, and physical sensing:

Cloud Computing Models: IaaS, PaaS, SaaS & BaaS

  • IaaS (Infrastructure as a Service): Raw virtualized hardware resources (servers, storage, networking) such as AWS EC2 or Google Compute Engine.
  • PaaS (Platform as a Service): Managed execution environment where developers deploy code without server management (e.g., Heroku, Google App Engine).
  • SaaS (Software as a Service): End-user web applications delivered over the internet (e.g., Gmail, Google Drive, Microsoft 365).
  • BaaS (Backend as a Service): Cloud services providing pre-built backend capabilities—such as user authentication, realtime databases, and push notifications—via client SDKs. Google Firebase is a quintessential BaaS.

What a Cloud Database Is & Firebase Realtime Database

Unlike relational SQL databases relying on rigid tabular schemas, Firebase Realtime Database is a cloud-hosted NoSQL database where all data is stored as a giant hierarchical JSON tree. When any client updates a key, all connected clients receive the update in real-time via persistent WebSockets without polling.

Authentication vs Authorization

Authentication (AuthN) verifies identity ("who are you?") using credentials such as email and password. Authorization (AuthZ) determines permissions ("what are you allowed to do?") using security rules that restrict who can read or write specific database paths.

Environmental Sensing: DHT11 & LDR

  • DHT11: Capacitive humidity sensor and thermistor with custom single-wire digital serial transmission.
  • LDR (Light Dependent Resistor): Photoresistor whose electrical resistance decreases as incident light increases, read via an ADC voltage divider circuit.

Section 05

Wiring & Setup

Component ESP32 Pin Description
DHT11 DATA Pin GPIO 4 Bidirectional single-wire digital signal with 10kΩ pull-up resistor.
DHT11 VCC / GND 3.3V / GND Sensor power supply lines.
LDR Voltage Divider Output GPIO 34 (ADC1_CH6) Analog input reading voltage variations proportional to ambient light.
Relay IN Pin GPIO 26 Digital control signal driving relay transistor coil (Active LOW/HIGH).
Relay VCC / GND 5V (VIN) / GND Provides 5V coil power to prevent microcontroller reset under load.
Section 06

Implementation

Below is the core firmware utilizing the FirebaseESP32 library:

ESP32_Firebase_Monitoring.ino 
#include <WiFi.h>
#include <FirebaseESP32.h>
#include <DHT.h>

#define WIFI_SSID       "YOUR_WIFI_SSID"
#define WIFI_PASSWORD   "YOUR_WIFI_PASSWORD"
#define FIREBASE_HOST   "YOUR_PROJECT_ID-default-rtdb.firebaseio.com"
#define FIREBASE_AUTH   "YOUR_FIREBASE_DATABASE_SECRET"

#define DHTPIN          4
#define DHTTYPE         DHT11
#define LDRPIN          34
#define RELAYPIN        26

DHT dht(DHTPIN, DHTTYPE);
FirebaseData fbdo;
FirebaseAuth auth;
FirebaseConfig config;

unsigned long lastSend = 0;

void setup() {
  Serial.begin(115200);
  pinMode(RELAYPIN, OUTPUT);
  digitalWrite(RELAYPIN, LOW);
  dht.begin();

  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nWiFi Connected!");

  config.host = FIREBASE_HOST;
  config.signer.tokens.legacy_token = FIREBASE_AUTH;
  Firebase.begin(&config, &auth);
  Firebase.reconnectWiFi(true);
}

void loop() {
  // Push environmental telemetry every 3 seconds
  if (millis() - lastSend > 3000) {
    lastSend = millis();

    float temp = dht.readTemperature();
    float hum = dht.readHumidity();
    int light = analogRead(LDRPIN);

    if (!isnan(temp) && !isnan(hum)) {
      Firebase.setFloat(fbdo, "/environment/temperature", temp);
      Firebase.setFloat(fbdo, "/environment/humidity", hum);
      Firebase.setInt(fbdo, "/environment/lightLevel", light);
      Serial.printf("Published: T=%.1fC, H=%.1f%%, L=%d\n", temp, hum, light);
    }
  }

  // Check remote bulb control state from database
  if (Firebase.getBool(fbdo, "/controls/bulbStatus")) {
    bool bulbOn = fbdo.boolData();
    digitalWrite(RELAYPIN, bulbOn ? HIGH : LOW);
  }
}
Section 07

Configuration

Firebase Project Setup Guide

  1. Go to console.firebase.google.com and create a new project.
  2. In the left sidebar, navigate to Build > Realtime Database. Click Create Database.
  3. Select your database location and start in Test Mode for initial prototyping.
  4. Set secure database rules: 
    {
  "rules": {
    ".read": "auth != null",
    ".write": "auth != null"
  }
}
  5. Under Authentication, enable Email/Password sign-in for the web dashboard.
  6. Copy your Project API Key and Database URL into your local configuration file.

Section 09

Challenges & Fixes

Problem DHT11 frequently returned NaN (Not a Number) for temperature and humidity.
Investigation The DHT11 sensor requires at least 1–2 seconds between consecutive read requests. The loop was querying the sensor too fast.
Solution Enforced non-blocking 3-second sampling interval using millis() - lastSend > 3000.
Outcome Accurate, reliable telemetry reads without stalling system responsiveness.
Problem ESP32 reset unexpectedly when the relay switched on.
Investigation Electromagnetic inrush current and inductive kickback from the relay coil caused a 3.3V rail voltage brownout.
Solution Powered the relay module from the 5V (VIN) rail and added a decoupling capacitor across power rails.
Outcome Completely stable switching behavior with no brownout resets.
